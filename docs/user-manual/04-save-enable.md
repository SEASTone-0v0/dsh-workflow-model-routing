# 第 5 章　保存、启用、复制与恢复预设

这一章是防止“看起来改了，实际没生效”或“以为只改草稿，实际启用了模式”的核心章节。

## 5.1 页面上的三种状态

| 状态 | 含义 | 会发生写入吗 |
| --- | --- | --- |
| 选中某模式 | 当前正在查看哪份草稿 | 不会 |
| 显示「未保存」 | 草稿或授权与已存配置不同 | 尚未持久化 |
| 显示「当前」 | Host 记录的 `currentModeId` | 已经启用过，不等于正在编辑 |

你可以选中普通模式编辑，同时当前模式仍是经济模式。不要因为标签排在同一排就把“选中”当成“启用”。

## 5.2 保存设置做什么

点击「保存设置」时，按变化内容执行：

1. 当前模式草稿有变化：提交 `modeId`、完整草稿和 `expectedRevision`。
2. 授权有变化：同步全局授权。
3. 保存的是当前模式：同步当前模式角色到实时全局角色存储。
4. 保存的是非当前模式：只同步授权；全局角色仍使用已存当前模式的角色，避免无关草稿覆盖实时配置。

模式保存成功后，对应草稿会更新为服务器返回值。全局同步失败时会显示“模式已保存但全局同步未完成”一类警告，不能把它当成全部成功。

### 保存不做的事

- 不切换 `currentModeId`。
- 不创建新的活动快照。
- 不把 Lead 写入今后主会话默认选择。
- 不对所有路线做真实连接测试。
- 不保证旧会话改用刚保存的草稿。

保存路径使用 `skipValidation` 以避免把普通保存变成真实探测；严格路线与推理校验是启用阶段的责任。

## 5.3 启用该模式做什么

「启用该模式」只在草稿干净时允许继续。若有未保存变化，先保存。

启用会：

1. 按已存 revision 做并发检查。
2. 校验被引用路线的授权和推理能力。
3. 设置 `currentModeId`。
4. 创建新的 `activeSnapshot`。
5. 将 Lead 写入今后主会话的默认模型选择。
6. 如果默认选择写入失败，尝试恢复先前的 Lead 默认选择并报告错误。

启用不是“保存按钮的另一种叫法”，它会改变当前模式与今后默认 Lead。

### 严格校验可能拒绝的情况

- 引用路线未授权；
- 固定推理档位不在目标模型声明集合中；
- smartMap 含有目标模型不支持的档位；
- 模式缺少必要路线；
- 配置 revision 已被其他窗口修改。

启用失败时按完整错误逐项修正，不要为了通过校验随意授权不明路线或猜档位。

## 5.4 活动快照与会话冻结

启用产生的是新的活动配置；会话实际使用还取决于冻结时机：

```text
启用模式 → activeSnapshot
新 Agent/会话首次需要配置 → 冻结自己的会话快照
后续 role_subagent → 优先读取该会话已冻结快照
```

已有快照不会因为再次保存或启用而被通用 `ensureSessionSnapshot` 自动替换。因此：

- 新配置可影响今后新会话；
- 已打开会话可能继续使用旧快照；
- 说明书或实时 `/modes` 返回的最新草稿，不等于当前会话冻结快照。

若需要严格核对某会话的路线，应查看该会话自己的运行时证据，而不是只看设置页。

## 5.5 复制模式

1. 选中目标模式。
2. 在「复制自…」选择来源模式。
3. 确认复制。
4. 检查目标草稿，再保存。

复制内容包括 Lead、协作建议、角色、协作身份覆盖和任务目标配置。它使用**来源模式的已存配置**，不是来源模式尚未保存的临时编辑；目标原有草稿会被覆盖。

复制不自动启用目标模式，也不等于复制来源的授权列表——授权本来就是全局共享的。

## 5.6 恢复预设

「恢复预设」针对当前选中的模式：

- Lead、协作建议、协作身份和任务目标恢复为后端推荐预设；
- 内置角色按 ID 使用预设版本；
- 自定义角色保留；
- 预设引用路线以**只增不删**方式并入授权草稿；
- revision 保留，仍需保存。

它不会立即启用，也不会删除现有额外授权。恢复后应逐项检查，因为“推荐预设”不等于当前账户已经验证全部可用。

## 5.7 保存全部草稿与单模式保存

「模型配置」里的「保存全部草稿(n)」用于 AI 或多模式编辑后的批量保存。它按顺序处理各模式，再同步全局存储；**不是跨所有模式的一次原子事务**。部分模式成功、部分失败是可能的，必须看每个结果。详细操作见第 7 章。

## 5.8 revision 冲突怎样处理

出现 409 或“配置已被其他窗口修改”时：

1. 停止重复点击保存。
2. 记录自己尚未保存的关键改动。
3. 让页面重新载入最新配置。
4. 对比后重新应用改动。
5. 再保存或启用。

`expectedRevision` 是防覆盖机制，不是需要绕过的障碍。全局授权冲突与单个模式冲突可能分别出现。

## 5.9 推荐操作顺序

```text
选模式
  → 修改 Lead/角色/授权
  → 检查未保存标记
  → 保存设置并确认全局同步成功
  → 需要时做能力刷新或明确授权的连接测试
  → 启用该模式
  → 用新会话或运行时证据验证实际路线
```

## 5.10 验收清单

- [ ] 能区分选中、未保存和当前模式。
- [ ] 保存非当前模式不会把它的角色覆盖到实时全局角色。
- [ ] 模式保存成功但全局同步失败时，没有宣称全部成功。
- [ ] 启用前草稿已保存，启用后核对当前模式与活动快照。
- [ ] 没有承诺旧会话立即采用新配置。
- [ ] 复制模式使用来源的已存配置，恢复预设只增授权且保留自定义角色。
- [ ] 409 通过重新载入与合并解决，没有盲目重试。
