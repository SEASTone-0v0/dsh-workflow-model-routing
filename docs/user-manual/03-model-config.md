# 第 4 章　模型配置：授权、能力、分层与连接测试

「模型配置」管理全局授权草稿和模型元数据，也提供 AI 配置入口。这里的“可见”“授权”“测试通过”是三个不同状态。

## 4.1 授权是全局共享的

四套模式各自有 Lead、角色和协作配置草稿，但**授权列表全局共享**。

因此：

- 给经济模式引用的模型添加授权后，其他模式也能在已授权范围内选择它；
- 撤销授权前必须检查所有模式的引用；
- 保存非当前模式时，也会同步全局授权，但不会把非当前模式的角色提升为实时全局角色。

## 4.2 添加授权

1. 在授权列表下方的下拉框选择 `provider / model`。
2. 点击「添加授权」。
3. 列表出现新行，只表示授权草稿增加。
4. 点击「保存设置」；如需应用模式，再明确启用。

添加时会按 `provider + model` 检查精确重复。相同模型名但不同 provider 是不同路线，不能因为显示名相似就删除其中一条。

### 同名模型的优先顺序

在自动修复、AI 候选规范化等适用路径中：

1. 精确模型 ID 优先选择 `kimi-subscription`；
2. 其次选择 `antigravity`；
3. 两组没有精确 ID 时，才考虑同 provider 或其他组；
4. 只有规范化显示名能**唯一匹配**时才跨模型 ID 修复；有歧义则报告，不盲目替换。

这不妨碍用户手工选择其他已授权的非 vision 路线。优先规则不是供应商禁用规则。

## 4.3 撤销授权与引用保护

点击某行的「撤销」：

- 如果该路线仍被 Lead、角色、协作身份、顾问或配对引用，页面会阻止撤销并列出引用；
- 没有引用时才从授权草稿移除；
- 保存后才写入全局配置。

撤销授权不会自动把角色改派到另一个模型，也不会自动选择备用或升级路线。先调整引用，再撤销，是更安全的顺序。

## 4.4 恢复默认授权

「恢复默认授权」会把**授权草稿替换为后端推荐授权集合**，不修改角色分配，保存后才生效。

它与「恢复预设」不同：

| 操作 | 影响 |
| --- | --- |
| 恢复默认授权 | 替换授权草稿，不改角色 |
| 恢复预设 | 恢复当前模式的 Lead、角色、协作等推荐草稿，保留自定义角色，并把引用路线以只增不删方式并入授权 |

恢复默认授权可能移除你手工添加的授权，因此操作前应核对草稿与引用。

## 4.5 能力缓存与推理档位

授权表显示能力缓存状态、可用推理档位和默认档位。路线编辑器只应使用目录明确声明的能力。

| 状态 | 使用方式 |
| --- | --- |
| 有效且声明 efforts | 可选择受支持固定档位或模型默认 |
| 声明无 efforts | 只使用模型默认 |
| 未知、失效或过期 | 不猜固定档位；先刷新元数据，必要时显式改回模型默认 |
| 旧固定档位已不受支持 | 页面提示；不会为了“修复”而静默改写用户草稿 |

「刷新能力」读取本地/目录元数据并更新能力缓存，**不等于真实生成连接测试**。

## 4.6 测试连接

点击「测试连接」会把当前授权和角色提交给验证接口，对相关路线发起最小真实模型请求。

它可能：

- 消耗少量 token；
- 产生费用或占用订阅额度；
- 暴露权限、凭据、限流、网络或模型访问错误；
- 与纯目录刷新得到不同结果。

测试结果只证明当次请求及其输入条件，不保证所有上下文长度、图像输入、工具调用、并发或后续生成质量都合格。未得到用户明确授权时，不要把自动验收脚本变成真实批量调用。

## 4.7 分层与刷新分层

分层用于展示经济/普通/性能等参考信息，帮助阅读授权列表。它不再决定某供应商能否被选择，也不是自动路由依据。

「刷新分层」更新分层元数据。分层变化不应被解释为：

- 自动撤销授权；
- 自动改变角色；
- 自动升级或降级模型；
- 禁止某供应商。

## 4.8 授权表各列怎样读

| 列 | 含义 |
| --- | --- |
| 测试连接 | 最近一次页面验证结果；未测试与失败不同 |
| 已授权模型 | 精确 `provider / model` |
| 分层 | 展示性参考标签 |
| 能力缓存 | 本地能力状态，不是实时订阅证明 |
| 推理档位 | 目录声明的档位与默认值 |
| 引用位置 | 当前哪些配置引用该路线 |
| 操作 | 撤销授权；被引用时阻止 |

## 4.9 vision 别名与原生图像能力

配置中心不展示、也不让 AI 使用 `-vision` 派生别名；旧配置会迁移到匹配的非 vision 路线。

这不是删除图像理解能力：

- 非 vision 模型若声明 `inputModalities` 包含 `image`，仍是原生多模态模型；
- `vision` 是角色 ID，不等于必须使用 `-vision` provider；
- 不卸载 DSH Vision Router，也不隐藏 Host 的全局聊天模型选择器。

## 4.10 AI 区域的位置

「模型配置」顶部还有：

- 一键配置；
- 一键推荐；
- 保存全部草稿。

这些按钮会产生真实模型请求或批量写入，详细步骤与故障处理见第 6、7 章。不要为验证目录而反复点击它们。

## 4.11 验收清单

- [ ] 新增授权只改变草稿，保存后才持久化。
- [ ] 被引用路线不能直接撤销。
- [ ] 已区分恢复默认授权与恢复预设。
- [ ] 能力刷新没有被当成真实连接测试。
- [ ] 连接测试的真实请求与费用边界已说明。
- [ ] 同名模型优先规则没有变成手工选择禁令。
- [ ] `-vision` 别名不可选，但原生图像输入能力仍被保留。
