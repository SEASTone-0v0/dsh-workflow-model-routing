# 第八章　SSS 协作网络：从用户请求到专业角色

本章配合交互图阅读：

[打开 SSS 协作网络](../../../output/sss-network-20261117/sss-network.html)

图中的 SSS 是一个假设的综合任务：竞品证据、销售分析、看板和汇报。它用于解释协作关系，**不是已经执行过的业务项目，也不是框架自动运行的固定流程**。

## 8.1 先分清图里的四种东西

| 图中对象 | 代表什么 | 不代表什么 |
| --- | --- | --- |
| 节点 | 一次判断、模型工作、Host 执行、记录或交付动作 | 必然已启动的 Agent/进程 |
| 箭头 | 数据、控制、状态、咨询或返工关系 | 所有节点同时运行 |
| 区域 | 阶段、职责或任务层级分组 | 同区就是同一 Agent/模型，或可并行 |
| 配置下拉框 | 查看某套已保存模式下的角色路由参照 | 切换 Host 当前模式，或读取本会话冻结快照 |

模型名称来自配置快照，不是永久推荐。阅读时以图内 `capturedAt`、版本和说明为准；真实派工仍以当前会话快照、授权、能力和入口为准。

## 8.2 SSS → A/B/C → 子任务怎么拆

### 顶层任务 SSS

用户给出目标、材料、限制和验收要求。根 Agent 先形成任务契约，而不是直接把全部材料群发给 14 个角色。

### 三个一级工作包

| 工作包 | 目标 | 子任务示例 |
| --- | --- | --- |
| A：证据 | 建立可追溯的研究证据包 | A1 来源检索、A2 长文整理、A3 图文研究；必要时 A3v 图像细读 |
| B：分析 | 建立数据口径、干净数据和可复现计算 | B1 清洗与数据字典 → B2 统计与核验 |
| C：成品 | 把证据和分析变成可交付结果 | C1 看板/代码、C2 叙事、C3 编辑与报告 |

A 和 B 可以在输入允许时并行准备；C 依赖所需的 A/B 成果。B2 不应在 B1 之前启动，C3 也不应在核心输入尚未齐备时假装完成最终报告。

## 8.3 35 个节点速查

### 任务定义与规划

| 节点 | 作用 |
| --- | --- |
| U | 用户任务 SSS 与原始材料 |
| L0 | 根 Agent 理解目标、边界、验收和权限 |
| P | 隐私与材料分级；确定可出云子集 |
| CAP | 发现 skill、工具、API、模型与模态能力 |
| SEC | 整理需求、约束和材料索引 |
| ARC | 提出 A/B/C 拆解和依赖草案 |
| CH | 按需挑战方案、寻找反例与风险 |
| L1 | 根 Agent 批准任务书、写入范围和 DAG |
| LED | Host 共享任务账本与 revision 记录 |

### 工作包细分与启动

| 节点 | 作用 |
| --- | --- |
| AS | A 拆成 A1/A2/A3，约定证据格式 |
| BS | B 拆成 B1/B2，约定字段与指标 |
| CS | C 拆成 C1/C2/C3，约定成品接口 |
| SCHED | 根 Agent 根据依赖、输入和容量选择就绪任务 |
| ROUTE | 确定性解析入口、角色、provider/model/effort 或拒绝原因 |
| SPAWN | Host 创建子 Agent，返回 childId 或失败 |
| CLAIM | 执行者读取最新任务并按 revision 认领 |

### 专业执行与工具循环

| 节点 | 作用 |
| --- | --- |
| A1 | 检索、来源比较与证据定位 |
| A2 | 长材料分段整理与索引 |
| A3 | 图文交叉研究，提出图像细读需求 |
| AV | 按需图像观察/OCR，结果回传 A3 |
| B1 | 数据口径、清洗、数据字典和日志 |
| B2 | 计算指标、检查边界和一致性 |
| TOOL | 每个执行者反复进行“模型选动作 → Host 执行工具 → 结果回上下文” |
| COORD | 可选的分支协调角色；不是树根 Lead |

### 汇合、成品与验收

| 节点 | 作用 |
| --- | --- |
| JOINA | 汇总 A1/A2/A3，保留来源、矛盾和空白 |
| C1 | 看板/代码实现与真实测试 |
| C2 | 叙事与表达方案，事实仍来自证据 |
| C3 | 报告编辑、版式和可交付文件 |
| SEC2 | 产物索引、证据清单和台账核对 |
| REV | 独立审查原始证据、数字、代码和界面 |
| ADV | 复杂阻塞或高风险时的按需顾问 |
| REPLAN | 返工、再拆分、更新依赖和重新排队 |
| PACK | 执行者回传路径、测试、风险并显式更新任务 |
| FINAL | 根 Agent 对照原始验收标准集成复核 |
| DELIVER | 展示成果、限制和文件；用户反馈进入新一轮 |

14 个角色是配置中的职责类型，不等于 14 个常驻 Agent，也不等于 35 个节点各需要一个新 Agent。一个角色可承担多个节点，一个执行者也可能进行多轮工具调用。

## 8.4 三种分层视图怎么用

### 阶段区域

按任务先后查看：输入与分级、规划、拆分、派工、执行、汇合、成品、复核、交付。适合回答“现在进行到哪一步”。

### 职责层级

| 区域 | 含义 |
| --- | --- |
| R0 | 用户与隐私授权边界 |
| R1 | 根 Agent 的决策、计划与最终责任 |
| R2 | 专业角色的模型工作 |
| R3 | Host 工具、路由、创建与认领等确定性执行 |
| R4 | 共享任务账本与状态证据 |

适合回答“谁负责判断、谁真正执行、谁保存状态”。

### 任务层级

| 区域 | 含义 |
| --- | --- |
| T0 | 顶层 SSS |
| T1 | A/B/C 一级工作包 |
| T2 | A1/B1/C1 等子任务 |
| T3 | AV 等更深层按需任务 |
| TX | 跨任务公共支撑，例如工具循环、路由、台账和验收 |

同一层级不表示并行，同一颜色也不表示同一执行者。并行必须另外满足依赖、输入授权、写入隔离和容量条件。

## 8.5 交互操作

1. **配置参照**：切换四个保存模式，只改变图内模型参照，不修改 Host。
2. **分层视图**：切换阶段、职责和任务层级。
3. **＋ / −**：缩放网络。
4. **全网**：恢复全网视图。
5. **取消聚焦**：清除节点/搜索聚焦。
6. **搜索**：输入角色名、节点 ID（如 A1）或“台账”。
7. **显示全部工具循环边**：默认减少工具边 clutter；勾选后查看完整模型/工具往返。
8. **点击节点**：右侧查看角色、模型、判断类型、输入、工作、输出、依据、存储位置和上下游。
9. **完整矢量网图**：打开 SVG，适合放大和静态阅读。
10. **所有节点详细契约**：不点击也可展开阅读全部节点卡片。

边颜色区分数据/成果、派工/控制、按需咨询、返工和账本状态。箭头表示关系，不是执行时间戳。

## 8.6 两个执行位的阅读示例

若插件并发上限为 2，可把图理解为有限执行位上的调度，而不是一次启动全部角色：

1. Lead 澄清与查能力，秘书可由 Lead 兼任。
2. 架构师提出 DAG；挑战者按需，不默认占用执行位。
3. 执行位 1 做 A1，执行位 2 做 B1。
4. 某位完成后可补位 A2 或 B2；不要求整批 barrier。
5. A3/AV 依输入和容量排队，嵌套派工不增加总额度。
6. A/B 必需输入齐备后，再安排 C1/C2，最后 C3。
7. REV 不通过则返工、重测、再审，不直接结项。

这是示例安排，不是框架自动生成的批次。插件并发也不限制直接原生 subagent、其他会话或 task_board 运行。

## 8.7 阅读网络时最常见的误判

- 把角色名当成独立人格或自主决策者。
- 把 saved 配置当成当前会话冻结路由。
- 把任务记录当成已经启动的执行会话。
- 把箭头当成全部并行或自动调用。
- 把 backup/upgrade 连线当成失败自动切换。
- 把顾问条件当成后台自动触发器。
- 把 reviewer 结论当成不需要根 Agent 最终验收。
- 把图中的 SSS 示例 ID 当成 Host 返回的真实 taskId。
