# 第 2 章　主会话与派工控制

本章只讲第一个主模块：Lead 默认路线、插件派工入口和插件并发。协作身份覆盖、协作建议已移到「模型与角色中心」的高级区域。

## 2.1 Lead 主模型

### 作用

这里设置的是**当前模式中的 Lead 配置**。模式成功启用后，它会作为今后主会话的默认模型路线；它不是“当前页面正在运行的模型”的实时显示器。

### 操作

1. 在「Lead 主模型」下拉框中选择 `provider / model`。
2. 设置固定推理档位，或选择「模型默认」。
3. 点击「保存设置」。
4. 若希望应用为当前模式并更新今后默认选择，再点击「启用该模式」。

「模型默认」优先；只有用户明确选择固定档位时才向下游传递固定 `reasoningEffort`。不要把 smartMap 的自动分档文字理解为这里已经实现的动态调度。

### 可选项从哪里来

下拉框来自当前已授权模型与可用目录。v2.6.3 起，`-vision` 派生别名不在这里展示；原生支持图像输入的非 vision 模型仍可显示。模型名称是否出现在目录里，不代表订阅一定有权访问。

### 不做什么

- 不在打开设置页时修改当前会话模型。
- 不在保存草稿时修改主会话默认选择。
- 不保证当前已存在会话立即换模型。
- 不因为这里的 Lead 选择而自动改变 coder、researcher 等专业角色。

## 2.2 固定档位与「模型默认」

| 选择 | 行为 | 建议 |
| --- | --- | --- |
| 模型默认 | 使用目标模型自己的默认推理政策 | 不确定时首选 |
| 固定档位 | 只传目录明确声明支持的档位 | 不猜 `low/high/xhigh` 等枚举 |
| smartMap | 模式里可保存分档配置，但当前 Lead 应用不会逐任务动态分档 | 当作配置/建议信息，不当作自动调度承诺 |

切换到推理能力不同的目标路线时，迁移工具会把不兼容配置降为模型默认并给出警告；这不是静默选择另一模型。

## 2.3 原生 `role_subagent` 派工

### 「注册 role_subagent 工具」开关

开启后，插件注册角色派工工具。它的工作方式是：

1. 读取当前会话冻结的模式快照。
2. 根据参数和角色表解析路线。
3. 检查授权与能力。
4. 调用 DSH 原生 `subagents.startActivation` 创建子代理。

插件负责角色映射与检查，**真正创建 Agent 的是原生 DSH 服务**。

### 开关作用域

关闭它只表示关闭插件的 `role_subagent` 入口，不等于关闭：

- 宿主原生的 `subagent`、`subagent_fork`；
- `subagent_claude_code`、`subagent_codex` 等外部后端；
- 任务板或定时任务；
- 当前 Agent 已经拥有的其他工具。

工具是否实际出现在本轮工具列表，还取决于 Agent preset、Host 配置和运行时能力；仅开启插件开关不保证每个会话都能调用。

### 适用与不适用

| 情况 | 推荐方式 |
| --- | --- |
| 当前有 `role_subagent`，希望按专业角色和模式快照派工 | 使用插件工具 |
| 当前只有原生 `subagent`，且需要明确指定 provider/model | 使用原生工具 |
| 需要 Claude Code / Codex 专用后端 | 使用对应外部子代理工具 |
| 只是简单问答或小编辑 | 可直接在当前会话完成 |

没有「任务超过某复杂度就自动从原生切到插件」的全局规则。

## 2.4 并发派工上限

这是**插件 `role_subagent` 的并发预留上限**，不是整台机器、所有任务板或所有原生 Agent 的统一上限。

### 操作

1. 输入正整数上限。
2. 正常建议最多 2 个执行者；复杂任务可按资源调整，但不要默认无限扩张。
3. 保存草稿，按需启用模式。

### 实际含义

- 插件在创建前预留槽位，结束时释放。
- 达到上限时返回明确错误，不是把任务悄悄排队后宣称已经启动。
- 原生直接派工、其他插件和任务板不共享这个计数器。
- 共享任务记录的 owner、revision、write scope 仍需要单独管理。

### 写入范围互斥

并发上限为 2 不代表两个执行者可以修改同一文件。任务书仍需列明：

- 目标与输入；
- 各自写入路径；
- 禁止事项；
- 验收命令；
- 交付物与升级条件。

## 2.5 与「启用该模式」的关系

主会话模块本身没有独立的“立即生效”按钮。它随当前模式草稿一起保存，再由模式启用流程处理：

1. 校验授权与推理能力。
2. 设置当前模式和活动快照。
3. 写入今后主会话的 Lead 默认选择。
4. 若默认选择写入失败，恢复先前的 Lead 默认选择并报错。

页面上的「当前模式」标签、下拉框选择和实际启用状态不是一回事；以启用结果为准。

## 2.6 常见操作示例

### 只改 Lead，不动角色

进入主会话模块 → 修改 Lead → 保存 → 启用。角色草稿保持不变，启用后角色按模式快照供 `role_subagent` 使用。

### 只想关闭插件角色入口

取消「注册 role_subagent 工具」→ 保存 → 启用。随后根据当前 Agent 的真实工具列表选择原生派工，不要假设全局都不能再创建子代理。

### 并发报错

先检查是否已有插件角色子代理占用槽位，再决定是否等待、减少派工或调整上限。不要通过重复点击制造多个相同任务，也不要把任务板创建记录当成正在运行。
