主用 (primary) / 备用 (backup) / 升级 (upgrade) 触发机制与五重区分对照表

在插件 role_subagent 路由解析（three-mode-release-20261114/lib/execution.js:275–363）中，每个标准角色都拥有 主用 (primary)、备用 (backup)、升级 (upgrade) 三条独立槽位。它们既不是自动重试链，也不能与全局运行模式、协作身份覆盖或顾问节点混为一谈：

维度 / 档位何时触发（触发信号）谁做决策与如何传参ROUTE (execution.js) 解析行为严格边界（不是什么）
主用 primary任务依赖已满足、材料已获准、首次常规派工（如 A1/B1/C1 首次启动）根 Agent 在 SCHED 阶段调用 role_subagent({ roleId, prompt })（不传 tier 或显式传 tier:"primary"）若未传单次 override 与有效 teamRole，默认读取 role.primary，校验全局授权与声明的推理档位不是必然成功的保证；若主用路线未配置或未授权，直接返回 no-route / unauthorized，不会静默跳到 backup
备用 backup主用路线发生通道/环境故障：如连接超时、429 速率限制、订阅额度耗尽、OAuth 刷新失败或服务端 5xx（SPAWN 或 TOOL 报错回传）错误证据进入 REPLAN，根 Agent 判断属于通道/可用性问题而非任务设计错误，在 SCHED 显式传入 tier:"backup" 重新派工读取 role.backup 并校验全局授权与能力缓存；生成的派工账本记录 tier="backup" 与 routeSource="role-backup"不是底层自动故障转移（Auto-Failover）；Host 绝不会在流式报错时偷偷替你重发第二次请求
升级 upgrade任务发生质量/复杂度瓶颈：如子任务跨模块复杂度远超预期、同一逻辑连续两次有证据失败、或 REV 独立审查发现深层缺陷打回（可配合 ADV 顾问评估）根 Agent 在 REPLAN 更新任务书或拆解后，在 SCHED 显式传入 tier:"upgrade"（常配合更高推理档位如 high/xhigh/max）读取 role.upgrade 并严格校验目标模型声明的 reasoningEffort；记录 tier="upgrade" 与 routeSource="role-upgrade"不是按 Prompt 长度或后台自动提档；在穷鬼/经济模式下同样保留客户自由配置的 upgrade 路线，不硬性封禁
优先级覆盖
override > teamRole > role[tier]		需要临时指定单次路线（override），或按四大协作身份（teamRole: planner / executor / reviewer / advisor）统一接管某类岗位调用 role_subagent 时显式传入 override:{provider,model} 或 teamRole:"planner" 等execution.js:302–318 严格按 单次 override ＞ 有效 teamRole ＞ role[tier] 顺序命中第一条非空路线若传入了有效 override 或非空 teamRole，本次将优先使用覆盖路线，此时改 tier 不会越过更高优先级覆盖
特殊角色与非三档节点
privacy / Root / Host		涉及敏感材料分级（P）、主会话根决策（L0/L1/SCHED/REPLAN/FINAL）、Host 账本与工具执行（LED/ROUTE/SPAWN/TOOL）P 由人工或获准本地检查；Root 由当前会话主模型直接判断；Host 由确定性代码执行execution.js:297 对 kind==="privacy" 不论传 primary/backup/upgrade 一律返回 privacy-role 拒绝云派发不要把配置表里 privacy-memory 的三档候选当成获准出云；也不要把主会话 Lead 当成子代理角色三档

主会话与派工控制：模式Lead默认模型、角色派工入口开关与插件并发。开关不禁用所有原生subagent，并发不是Host全局上限。

模型与角色中心：专业角色主/备/升级路线；高级区“协作身份覆盖”（仅显式teamRole生效，优先级 override > teamRole > role[tier]）；高级区“协作建议”（顾问条件不是自动执行规则）。

阶段区域表示先后阶段；职责层级表示用户、决策、专业工作、Host执行及账本；任务层级表示SSS、A/B/C、A1/A2…及公共支撑。三种维度不能相互代替：同区不代表同一Agent、同模型或可同时运行。跨区域箭头表示协作或数据交换，不表示越权。

关键底层逻辑：四类“Lead/角色/模式”不要混用

① 当前对话主模型：由 Host 会话决定；本图未读取该会话身份或冻结快照，不猜测实际供应商或推理强度。② 模式 Lead：保存的未来主会话默认路线。③ roleId=lead：可派发的“总协调员”角色路线，不是树根自动改名。④ planner/executor/reviewer/advisor：teamRole覆盖槽，不是四个常驻Agent。

当前活动模式由接口报告为 economy；已存在会话可能持有旧冻结快照，本页没有读取该会话快照，因此下拉框展示的是保存的配置参照，不能当成此次真实派工模型。切换下拉框只改变本图，不修改运行模式。
