# 第六章　AI 一键配置与一键推荐

本章只说明“模型配置”里的两个 AI 功能。它们都会真实调用你选择的已授权模型，可能产生订阅额度或 API 费用。

## 6.1 两项功能有什么区别

| 功能 | 输入 | 输出 | 是否直接保存/启用 |
| --- | --- | --- | --- |
| 一键配置 | 当前目录、授权和模式草稿 | 四个模式的 Lead、角色路由、团队参数等配置草稿 | 否 |
| 一键推荐 | 当前目录、授权和角色 | 每个模式、每个角色的候选模型及理由 | 否，也不自动改路由 |

“一键”表示一次发起整组 AI 工作，不表示无人工审核、无费用或一次点击完成全部保存和启用。

## 6.2 执行模型怎么选

两张 AI 卡片各自有“执行模型”下拉框，只列当前已授权模型。

- 一键配置和一键推荐可以使用不同执行模型。
- 执行模型只是本次生成配置/建议的 AI，不会因此自动成为 Lead 或角色路由。
- 列表可见、已授权都不保证当前账号有权限、额度或网络可用。
- AI 执行器不能使用插件的视觉别名；视觉角色由真实多模态模型承担。

两张卡片共享忙碌状态。一个 AI 任务尚未结束时，不会同时从本页面发起另一个 AI 任务。

## 6.3 一键配置的完整操作顺序

1. 先保存并检查现有重要配置；需要时自行备份。
2. 选择本次 AI 执行模型。
3. 点击“一键配置”。按钮显示进行中时，不要连续重复点击。
4. 等待四个模式逐项返回。后端按模式串行执行，单项失败会记录错误并继续其他模式，不自动重试、不静默换模型。
5. 查看每个模式的成功、失败和 warnings。
6. 返回“主会话与派工控制”“模型与角色中心”逐模式检查生成的草稿。
7. 检查“模型配置”是否新增了 AI 结果引用的授权项。
8. 再执行保存、全局保存和启用；这些不是 AI 自动完成的步骤。

### 成功结果如何合并

- 只有返回成功的模式才进入合并。
- 请求开始时会为四个草稿和授权列表做快照。
- 如果某个模式在 AI 运行期间被你手动编辑，返回时该模式不会被覆盖，并会显示跳过提示。
- AI 结果引用的路由会以精确 `provider/model` 并入当前授权草稿；你在 AI 运行期间新增的授权不会因旧快照被覆盖。
- “新增授权”仍只是页面草稿，必须后续保存才持久化。

### 部分成功不是全部成功

结果区按模式显示成功或失败。一个模式失败，不代表另外三个模式没有生成；同样，三个成功也不代表失败项可以忽略。不要只看最后一条总提示，要逐项检查。

## 6.4 一键推荐的结果怎么读

每个模式下按角色列出候选，主要字段如下：

| 字段 | 含义 |
| --- | --- |
| `provider / model` | 精确供应商与模型 ID |
| 本地目录 | 候选来自当前 Host 返回的目录 |
| 模型知识 | 候选来自执行模型自身知识，不等于实时市场调研 |
| 本机可用 | 当前目录中存在同一路由；仍不代表权限、额度或连接已验证 |
| 理由 / 优势 / 注意 | AI 的建议文本，需要人工复核 |

重要限制：

- “模型知识”不是联网检索证明，也不是价格、发行状态或账号权限的实时保证。
- 当前推荐结果主要是阅读材料，没有“把此候选一键写入角色”的按钮。
- 要使用候选，需回到授权和角色编辑器手动添加精确路由、检查能力、保存并启用。
- 不要根据相似显示名称猜测供应商或模型 ID。

## 6.5 异步任务和轮询

点击后，浏览器先向 `/ai/jobs` 提交一次 POST，取得 `jobId`，随后用 GET 查询任务，而不是保持一个长时间生成请求。

- 轮询间隔约 1 秒。
- 页面等待上限为 480 秒。
- 连续临时轮询失败会有限次容忍；达到连续失败上限后报错。
- 同一任务不会因轮询失败而自动再次 POST 生成。
- 后端逐项串行执行，减少同一订阅账号的并发压力。

## 6.6 超时、无响应和任务丢失

### 页面等待超时

出现 480 秒超时和 `jobId` 时，只说明页面停止等待；**不代表后端任务已取消或失败**。不要立即反复生成。先记录 jobId，检查 Host/网络状态，再决定是否重新发起。

### 无响应 / `no-response`

这通常表示请求没有得到可判定的 HTTP 响应。页面会尽量显示底层网络原因，例如连接拒绝、超时或读取失败。

此时不能简单认定“模型没工作”：请求可能已经到达 Host。先检查后端任务和网络，不要无脑连续点击。

### 任务不存在 / `gone`

任务句柄已无法查询。当前任务管理不是跨重启的持久工作流，页面也没有完整的“刷新后重新附着旧 jobId”恢复界面。Host 重启、任务被淘汰或句柄失效后，可能需要重新生成；重新生成前应确认旧任务没有继续产生费用。

### HTTP、权限、额度与模型错误

这些错误与轮询失败不同，应按显示的错误类别处理：

- 未授权：先在授权草稿中添加精确路由并保存。
- 模型无权限：检查账号套餐、模型权限或换用你明确选择的模型。
- 额度/限流：检查账号状态、并发和供应商限制。
- 思考档位错误：选择该模型实际声明支持的档位。

不要把所有失败都归结为网络，也不要用“目录里能看到”反驳权限错误。

## 6.7 AI 结果验收清单

- [ ] 我记录了本次使用的执行模型。
- [ ] 四个模式逐项成功或失败都已阅读。
- [ ] 被跳过的人工编辑模式已确认。
- [ ] 新增授权是我允许的路由，不是仅名称相似项。
- [ ] 每个 Lead/角色的主、备、升级和思考档位已人工检查。
- [ ] 推荐结果中的“模型知识”没有被误认为实时可用证明。
- [ ] 我没有把 AI 返回当成已经保存或启用。
- [ ] 需要真实可用性时，另行执行受控连接测试，而不是依赖推荐文字。
